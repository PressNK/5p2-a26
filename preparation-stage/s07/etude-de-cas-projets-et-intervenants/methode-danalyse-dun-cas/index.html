🔍 Comment analyser un cas d'entreprise

Cette section propose une série de cas pratiques inspirés de projets réels en entreprise. L'objectif n'est pas de résoudre un problème technique, mais de s'exercer à identifier les métiers, les tâches et les livrables nécessaires pour réaliser un projet — une compétence essentielle de travail en équipe multidisciplinaire.

La méthode d'analyse​

Pour chaque cas présenté dans les pages suivantes, la démarche suggérée est la même :

  1. Identifier les livrables — Qu'est-ce qui doit être produit à la fin du projet? (voir la notion de livrable vue à la semaine 3)
  2. Identifier les tâches — Quelles actions concrètes doivent être réalisées pour produire chaque livrable?
  3. Identifier les métiers impliqués — Qui, dans une équipe multidisciplinaire, est le mieux placé pour réaliser chaque tâche? (voir les métiers de la profession vus à la semaine 6)
  4. Ordonner les tâches dans le temps — Quelles sont les dépendances entre les tâches? Qu'est-ce qui peut être fait en parallèle? (voir le séquencement des tâches vu à la semaine 3)
Pourquoi cet exercice est important

En stage, on ne vous demandera pas nécessairement d'écrire du code dès le premier jour. On attendra souvent de vous que vous compreniez qui fait quoi dans un projet, et que vous soyez capable de situer votre propre contribution dans l'ensemble du travail d'équipe.

L'aide-mémoire​

1. Le livrable : un nom​

Un livrable est une chose qui existe à la fin du projet. Il se décrit avec un nom.

  • ✅ « Un réseau Wi-Fi qui couvre l'entrepôt »
  • ✅ « Un formulaire d'inscription en ligne »
  • ❌ « Configurer le Wi-Fi » → c'est une tâche (il y a un verbe d'action)
Le test du livrable

Posez-vous la question : « Est-ce que je peux le montrer ou le remettre au client à la fin? » Si oui, c'est un livrable.

N'oubliez pas les livrables qui ne sont ni du code ni du matériel, mais qui sont très fréquents : un document d'analyse des besoins, une recommandation d'achat, un guide d'utilisation, des utilisateurs formés.

2. La tâche : un verbe + un objet​

Une tâche est une action à faire pour produire un livrable. Elle commence par un verbe.

Rencontrer le client · Commander les tablettes · Configurer le Wi-Fi · Programmer le calcul · Tester le formulaire

Selon le type de projet, on retrouve presque toujours les mêmes verbes, dans le même ordre :

Type de projetLes verbes qui reviennent
Services et infrastructure numériquesChoisir → Commander → Installer → Configurer → Tester
Développement logicielAnalyser → Concevoir → Programmer → Tester → Mettre en ligne → Former

Le bon niveau de détail​

Une tâche ne doit être ni trop vague, ni trop détaillée. Une tâche est bien découpée quand :

  • elle est faite par une seule personne (un seul métier);
  • elle prend de quelques heures à quelques jours;
  • on peut dire clairement si elle est terminée ou non.
Trop vague ❌Bon niveau ✅Trop détaillé ❌
Faire le site WebProgrammer le formulaire d'inscriptionAjouter le bouton « Envoyer »
S'occuper des tablettesConfigurer les tablettes pour accéder à l'applicationBrancher le câble de recharge
Gérer le réseauInstaller le point d'accès Wi-FiVisser le support au plafond

3. Le métier : qui fait la tâche?​

Pour chaque tâche, choisissez le métier le mieux placé parmi ceux vus à la semaine 6. Chaque page de cas pratiques vous donne un tableau des métiers utiles pour ses cas.

  • Soyez précis : « développeur back-end » plutôt que « programmeur », « technicien réseau (niveau 2) » plutôt que « l'informaticien ».
  • Pensez au niveau : plus une tâche technique est complexe ou risquée, plus le niveau du technicien est élevé (1, 2 ou 3).
  • Justifiez votre choix : dans une petite entreprise, une personne peut faire plusieurs métiers. Ce qui compte, c'est de pouvoir expliquer pourquoi ce métier est le bon.

4. L'ordre : avant, après, en même temps​

Pour chaque tâche, posez-vous deux questions :

  • « De quoi ai-je besoin avant de pouvoir commencer? » On ne peut pas configurer une tablette qui n'a pas encore été commandée.
  • « Qu'est-ce qui peut être fait en même temps? » Pendant que les tablettes sont en livraison, le technicien réseau peut installer le Wi-Fi.
info

Il ne s'agit pas de classer les livrables du plus important au moins important. Il s'agit de trouver l'ordre dans le temps des tâches.

Le modèle de réponse​

Pour chaque cas, remplissez un tableau comme celui-ci, puis décrivez l'ordre des tâches. L'ordre des lignes du tableau n'a pas d'importance.

LivrableTâches pour le produireMétier
Une chose (un nom)Des actions (verbe + objet)Qui le fait?

Exemple guidé — Nouveau module d'inventaire​

Les commis de l'entrepôt désirent un nouveau module pour faciliter la gestion de la prise d'inventaire. Le logiciel devra être portable, car il sera utilisé autant sur un ordinateur que sur une tablette. Le nouveau module respectera l'écosystème actuel du logiciel. Avant de commencer, il faudra bien comprendre les besoins des commis.

Les commis devront utiliser de nouvelles tablettes, configurées pour accéder facilement à l'application Web. La tablette devra être robuste, car les commis travaillent en hauteur. Il faudra également un étui permettant une bonne prise en main.

Finalement, il faudra configurer et installer un point d'accès Wi-Fi pour couvrir tout l'entrepôt.

Étape 1 — Les livrables​

On repère les noms en gras dans la mise en situation. Ce sont les choses qui existeront à la fin du projet :

  1. Un document d'analyse des besoins
  2. Le module d'inventaire (application Web)
  3. Une recommandation des tablettes et des étuis
  4. Des tablettes configurées, avec leur étui
  5. Un Wi-Fi qui couvre tout l'entrepôt

Étapes 2 et 3 — Les tâches et les métiers​

LivrableTâches pour le produireMétier
Document d'analyse des besoinsRencontrer les commis de l'entrepôt; observer une prise d'inventaire; rédiger le document d'analyseAnalyste d'affaires
Module d'inventaire (application Web)Développer la logique d'affaires et l'API Web en respectant l'écosystème actuelDéveloppeur back-end
Développer l'interface Web, adaptée à l'ordinateur et à la tablette; tester sur les deux appareilsDéveloppeur front-end
Recommandation des tablettes et des étuisDéfinir les critères (robustesse, taille de l'écran, prise en main); comparer des modèles; recommander une tablette et un étuiAnalyste technique
Tablettes configurées, avec leur étuiCommander les tablettes et les étuis; configurer les tablettes pour accéder facilement à l'application; installer les étuisTechnicien informatique (niveau 1)
Wi-Fi qui couvre tout l'entrepôtVérifier où le signal est faible; installer le point d'accès; configurer le Wi-Fi; tester le signal partout dans l'entrepôtTechnicien réseau (niveau 2)

Pourquoi ces métiers?​

  • Analyste d'affaires : il faut comprendre comment les commis font l'inventaire aujourd'hui. C'est un travail d'écoute et d'analyse, pas un travail technique.
  • Développeur back-end : « respecter l'écosystème actuel » veut dire que le module doit communiquer avec le logiciel existant (logique d'affaires, API).
  • Développeur front-end : l'interface doit fonctionner autant sur un ordinateur que sur une tablette. C'est une question d'interface et d'expérience utilisateur.
  • Analyste technique : choisir une tablette robuste selon des critères n'est pas la même chose que l'installer. On compare des options avant d'acheter.
  • Technicien informatique (niveau 1) : configurer un appareil pour un utilisateur est une tâche typique du niveau 1.
  • Technicien réseau (niveau 2), et non niveau 1 : le Wi-Fi fait partie du réseau de toute l'entreprise. Une erreur de configuration pourrait couper l'accès à tout le monde ou créer une faille de sécurité. Ce n'est pas non plus du niveau 3, car on ajoute un point d'accès : on ne conçoit pas une nouvelle infrastructure.

Étape 4 — L'ordre des tâches​

  1. D'abord : l'analyse des besoins. Tout le reste en dépend.
  2. Ensuite, en parallèle :
    • les développeurs programment le module d'inventaire;
    • l'analyste technique choisit les tablettes et les étuis, puis le technicien les commande;
    • le technicien réseau installe le Wi-Fi.
  3. Quand les tablettes sont livrées : le technicien les configure.
  4. À la fin : on teste le module sur les tablettes, dans l'entrepôt, avec le Wi-Fi.
info

Remarquez que ce seul projet implique déjà 6 métiers différents, un bon exemple concret de travail en équipe multidisciplinaire!

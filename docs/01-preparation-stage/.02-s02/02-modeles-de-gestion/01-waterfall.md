# 🌊 La méthode Waterfall (cascade)

Le modèle classique par phases peut être problématique pour le développement logiciel : la période de temps entre l'identification du projet et sa clôture peut être très longue, et la validation du projet se fait difficilement sans avoir quelque chose de fonctionnel pour l'utilisateur.

Il existe donc plusieurs **modèles de gestion** propres au développement logiciel : **cascade (Waterfall)**, **V**, **spirale**, **itératif**, **Agile**.

:::info
Pour les projets d'infrastructure technique, l'approche classique (cascade) est généralement utilisée.
:::

## Origine

- Créée pour avoir un certain niveau d'**organisation** en développement logiciel
- Lorsque présentée pour la première fois, c'était pour **illustrer un modèle erroné**!
- Le « flow » va d'une étape à une autre, comme dans une **chute d'eau** — d'où le nom *Waterfall*

## Étapes

1. Requis
2. Conception
3. Implémentation
4. Vérification
5. Maintenance

Chaque étape doit être **complétée avant de passer à la suivante** — il n'y a (en théorie) pas de retour en arrière.

## Avantages

- **Facile à comprendre**
- Les phases sont **segmentées**
- **Parfait** si les requis sont bien compris dès le début
- Les phases **ne se chevauchent pas**

## Inconvénients

- **Peu flexible** si les requis changent
- Logiciel **fonctionnel qu'à la fin** du projet uniquement
- **Beaucoup de risques et d'incertitudes**

## En résumé

| ✅ Avantages                          | ❌ Inconvénients                          |
| -------------------------------------- | ------------------------------------------- |
| Facile à comprendre                    | Peu flexible aux changements                |
| Étapes bien segmentées                 | Rien de fonctionnel avant la fin             |
| Idéal si requis clairs dès le départ    | Beaucoup de risques et d'incertitudes        |

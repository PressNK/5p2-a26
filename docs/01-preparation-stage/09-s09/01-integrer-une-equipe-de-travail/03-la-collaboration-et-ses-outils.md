# 🤝 La collaboration et ses outils

## Les phases de l'évolution des équipes

Une équipe passe généralement par 3 niveaux dans sa façon de travailler ensemble :

### Niveau déresponsabilisation

- Travail en **silo**, ou en mode « chacun pour soi »
- Les **zones grises** (tâches que personne ne veut effectuer, ou qui ne sont pas clairement identifiées à une personne) sont :
    - souvent **ignorées**, car les tâches ne sont pas clairement définies;
    - souvent **non traitées**, car personne ne s'en soucie.

### Niveau responsabilisation

- Les tâches et les responsabilités sont **clairement identifiées** dans l'équipe
- Les limites des responsabilités sont **clairement établies**
- Les zones grises sont :
    - **facilement identifiables**;
    - **prises en charge**;
    - **ajoutées** aux tâches d'une personne spécifique.

### Niveau collaboration

- Même si une tâche n'est **pas dans les responsabilités** d'une personne, elle peut être **prise en charge** par une autre
- Les zones grises existent toujours, mais elles sont **rapidement prises en charge**

:::tip
Le niveau collaboration est l'objectif à viser pour une équipe multidisciplinaire performante — mais il ne s'atteint généralement pas du jour au lendemain. Il nécessite d'abord d'avoir bien établi le niveau responsabilisation.
:::

## Intra-équipe et inter-équipe

- La phase d'évolution peut être **différente selon les équipes** dans une même entreprise
- **Intra-équipe** : le fonctionnement interne d'une équipe
- **Inter-équipe** : le fonctionnement entre différentes équipes

:::caution
Une équipe peut être **très collaborative** dans son fonctionnement interne, mais fonctionner **en silo** avec les autres équipes de l'entreprise. Ne présumez pas que le niveau de collaboration de votre équipe reflète celui de toute l'organisation!
:::

## Les outils de collaboration

Il existe plusieurs outils de collaboration selon le contexte de travail.

### En développement logiciel

- **GitHub**
- **GitLab**
- **SVN**
- **Team Foundation Server** ou **Azure DevOps**

:::info
Pour les non-programmeurs, ces outils **ne répondent pas à leurs besoins** — ils sont pensés spécifiquement pour la gestion du code source.
:::

### Microsoft Teams

- Outil **très populaire** en entreprise
- Permet de collaborer avec **tous les métiers**, pas seulement les développeurs
- C'est un outil **généraliste**
- Il **ne remplace pas** les outils de collaboration spécialisés en développement (Git, etc.)

:::tip Pour aller plus loin
Vous avez déjà exploré en détail Microsoft Teams, Outlook, Planner ainsi que les outils Agile (Jira, GitHub Projects, Azure DevOps) dans la [section sur les outils et techniques de planification](../../03-s03/02-planification-du-travail-en-equipe/02-microsoft-365-pour-le-travail-dequipe/01-microsoft-teams.md) à la semaine 3. Ce cours vous rappelle que **le bon outil dépend du métier et du contexte** : un outil généraliste comme Teams cohabite très bien avec un outil spécialisé comme Git dans une même organisation.
:::

## En résumé

1. Une équipe évolue généralement de la **déresponsabilisation** vers la **responsabilisation**, puis vers la **collaboration**
2. Le niveau de collaboration peut varier entre le fonctionnement **intra-équipe** et **inter-équipe**
3. Les outils de collaboration se divisent en deux grandes catégories : les outils **spécialisés** (Git, Azure DevOps) pour les développeurs, et les outils **généralistes** (Teams) pour toute l'organisation
